# 将证据组织成文字和图表

## 一句话中心论点

可用句式：在【明确条件】下，【现有做法/理解】遗漏了【具体因素】；我们通过【可验证贡献】得到【有边界的新认识或能力】。

句式仅用于检查内容是否齐全，成稿可以自然改写。只有比较结果时说“在这些设置下改善”；有区分竞争解释的干预才升级为机制主张。

## 摘要

通常依次交代：具体问题 → 尚未解决的关键缺口 → 核心发现或设计原则 → 关键证据 → 结论边界。只放能代表中心论点的结果，注明比较对象和条件。没有数据时输出提纲或待填草稿，不编造胜率。

## 引言段落职责

1. 具体使用场景、目标及现有路径，让读者知道为什么需要这个问题。
2. 精确缺口；最好展示一个现象或反例，而不是列“复杂、昂贵、困难”。
3. 核心解释/观察及其与现有认识的区别，明确是发现还是假设。
4. 从解释导出设计，说明为何这些设计恰好对应问题。
5. 用少量关键证据概述贡献及范围。贡献条目可以是新理解、方法、资源或证明；不必硬凑三个。

这不是固定五段配方。理论论文可先给形式化问题；立场论文需说明价值前提与反方。

## 实验与图表

为每张核心图写三行：回答的问题、比较/控制、允许得到的结论。若图只能证明总体性能，不让它承担机制结论。

- 图 1 可以展示核心矛盾或能力，不必总是方法框图。
- 诊断图先控制简单混杂，再展示机制相关变化。
- 主结果同时体现质量、成本和重要退步，避免只截取赢家。
- 消融围绕竞争解释设计；逐个删模块只是其中一种。
- 边界图选择会改变结论的轴，如信息密度、分布偏移、精度、数据量。

## 改写时保留的信息

保留研究实际发生的顺序与逻辑顺序的区别：论证可以重新组织，探索性结果不能伪装成预先预测。技术细节保留到足以复核结论，不用术语密度制造贡献感。每段只推动一个关键问题；删去并不意味着隐去不利证据。

## 用户只有 idea 时

输出“候选故事 → 核心假设 → 预测 → 最小辨别实验 → 什么结果会放弃此故事”。不要先写一篇假想成功论文。若资源有限，优先选择能淘汰错误解释的实验，而非增加更多同质榜单。
